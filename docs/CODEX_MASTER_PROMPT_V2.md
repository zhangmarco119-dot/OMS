- 使用一个新的通用权限覆盖 V1 权限；
- 因新增工作台改变用户进入 V1 功能后的原有页面。

## 3. 仅 V2 新增模块暂时统一

# 五、到货上报模块

## 1. 目标

门店每次收到快递或配送货品后，员工或店长提交一条规范的到货记录。

每条记录至少包含：

- 快递面单照片；
- 拆包后的内部货品照片；
- 产品名称；
- 数量；
- 单位；
- 系统自动生成的规范描述；
- 门店；
- 提交账号；
- 到货时间；
- 提交时间。

管理员提交后立即在系统中看到未读消息，并可以查看每日汇总。

## 2. 流程

```text
进入到货上报
→ 填写到货日期和时间
→ 上传面单照片
→ 上传拆包货品照片
→ 添加一个或多个产品
→ 填写产品名称、数量和单位
→ 系统生成规范描述
→ 保存草稿或提交
→ 管理员收到消息
→ 每日汇总更新
```

## 3. 基础信息

系统自动记录：

- 到货 ID；
- 到货编号；
- 门店 ID；
- 门店名称快照；
- 提交账号；
- 提交人姓名快照；
- 创建时间；
- 提交时间；
- 更新时间。

用户填写：

- 实际到货日期；
- 实际到货时间，默认当前时间；
- 快递公司或配送方式，可选；
- 快递单号，可选；
- 补充备注，可选。

## 4. 面单照片

要求：

- 至少上传一张；
- 支持直接拍照；
- 支持相册选择；
- 上传前显示本地预览；
- 支持删除和重拍；
- 显示上传进度；
- 上传失败可重试；
- 上传未完成时不能提交。

提示文字：

> 请拍摄完整的快递面单或配送标签，确保关键信息清晰可见。

## 5. 货品照片

要求：

- 至少上传一张；
- 应在拆包后拍摄；
- 应尽量看清实际货品；
- 允许上传多张；
- 支持预览、删除和重拍；
- 上传未完成时不能提交。

提示文字：

> 请拆开包装后拍摄内部实际货品，确保货品和数量尽量清晰。

## 6. 产品明细

一条到货记录可以包含多个产品。

每个产品包含：

- 产品名称；
- 数量；
- 单位；
- 备注，可选；
- 正式商品 ID，可空；
- 是否未匹配正式商品；
- 排序。

产品名称：

- 优先从当前门店商品清单中搜索选择；
- 支持模糊搜索；
- 显示名称、规格和默认单位；
- 没有匹配结果时允许手动填写；
- 手动填写时标记 `is_unmatched_product = true`；
- 不自动写入正式商品表。

数量：

- 必填；
- 必须大于 0；
- 支持整数和小数；
- 不允许负数；
- 使用手机数字键盘。

单位：

- 选择正式商品后自动带出；
- 允许用户确认；
- 手动商品必须填写；
- 不同单位不得在统计中强行合并。

## 7. 自动生成规范描述

系统根据结构化明细自动生成描述，不要求员工重复输入同样的文字。

单个产品：

```text
OMEGA 原味酸奶到货 12 箱。
```

多个产品：

```text
本次到货：OMEGA 原味酸奶 12 箱，草莓酸奶 6 箱，酸奶杯 200 个。
```

实现并测试：

```ts
generateArrivalSummary(items)
```

要求：

- 顺序与明细一致；
- 数量格式正确；
- 单位不能为空；
- 中文标点正确；
- 明细变化时实时更新；
- 数据库同时保存结构化明细和生成描述；
- 不得只保存自由文本。

## 8. 状态

- `draft`
- `submitted`
- `viewed`
- `voided`

`draft`：

- 创建人可以编辑；
- 自动保存；
- 可以删除图片和产品。

`submitted`：

- 普通用户默认不可继续修改；
- 生成管理员通知；
- 进入每日汇总。

`viewed`：

- 记录查看管理员和查看时间。

`voided`：

- 仅管理员可作废；
- 必须填写原因；
- 不计入正常汇总；
- 历史记录和审计日志保留。

## 9. 提交校验

服务端必须检查：

- 用户属于该门店；
- 用户可操作 V2 新增模块；
- 当前状态是 draft；
- 至少一张面单照片；
- 至少一张货品照片；
- 至少一条产品明细；
- 产品名称非空；
- 数量大于 0；
- 单位非空；
- 没有图片正在上传；
- 自动描述与最新明细一致；
- 请求没有重复提交。

提交必须幂等，双击只能产生一条正式记录。

## 10. 管理员消息

提交成功后生成系统内消息。

显示：

- 门店；
- 提交人；
- 提交时间；
- 自动描述；
- 面单缩略图；
- 未读或已读；
- 到货编号。

示例：

> OMEGA酸奶（西直门店）于 14:32 提交一条到货上报：OMEGA 原味酸奶 12 箱。

点击消息后：

1. 标记已读；
2. 打开到货详情。

当前不要求短信、邮件、微信或企业微信推送。

## 11. 管理员详情

显示：

- 到货编号；
- 门店；
- 提交人；
- 到货日期和时间；
- 快递公司；
- 快递单号；
- 面单照片；
- 货品照片；
- 产品明细；
- 自动描述；
- 备注；
- 创建、提交和查看时间；
- 当前状态；
- 操作日志。

操作：

- 标记已查看；
- 作废；
- 下载图片；
- 导出当前记录；
- 返回列表。

## 12. 每日汇总

明细视图：

| 到货日期 | 到货时间 | 门店 | 产品名称 | 数量 | 单位 | 提交人 | 到货编号 |
|---|---|---|---|---:|---|---|---|

产品汇总视图：

| 到货日期 | 门店 | 产品名称 | 合计数量 | 单位 | 上报次数 |
|---|---|---|---:|---|---:|

规则：

- 按日期、门店、产品和单位聚合；
- 不同单位不合并；
- 作废记录不计入；
- 支持日期和门店筛选；
- 支持 Excel 导出。

文件名：

```text
到货汇总_2026-07-11.xlsx
```

Sheet：

1. 到货明细；
2. 产品汇总；
3. 上报信息。

# 十、UI/UX 总体要求

## 1. 风格

- 手机优先；
- 简洁、现代、专业；
- 页面留白充足；
- 卡片式布局；
- 圆角适中；
- 阴影轻；
- 避免夸张渐变和过度动画；
- 品牌色统一；
- 状态不能只靠颜色表达；
- 图标配合文字；
- 重要操作一眼可见。

## 2. 字体和操作尺寸

- 正文不小于 14px；
- 主要操作文字建议 16px；
- 页面标题 20–24px；
- 关键数字更大；
- 点击区域不小于约 44×44px；
- 主要按钮高度 48–56px；
- 输入框和卡片间距统一；
- 不出现文字和按钮挤压。

## 3. 手机适配

必须适配：

- iPhone；
- 安卓；
- 窄屏；
- iPhone 安全区域；
- 软键盘；
- Safari；
- Chrome；
- 微信内置浏览器的基础显示。

要求：

- 底部按钮避开安全区域；
- 输入框不被键盘遮挡；
- 不依赖 hover；
- 不出现横向滚动；
- 手机表格改用卡片或可控横向容器；
- 图片上传后布局不跳动；
- 关键动作适合单手操作。

## 4. 状态和错误

所有异步页面必须有：

- 骨架屏或加载状态；
- 空状态；
- 错误状态；
- 重试按钮；
- 权限不足页面；
- 网络异常提示；
- 保存状态；
- 上传进度。

提示必须具体，例如：

- “面单照片上传失败，请检查网络后重试。”
- “还有一张货品照片正在上传，暂时不能提交。”
- “数量必须大于 0。”
- “当前账号没有访问该门店记录的权限。”

不得只显示“操作失败”。

# 十四、RLS 和权限

所有新增表启用 RLS。

员工和店长在新增模块中可以：

- 创建本门店到货草稿；
- 修改自己未提交草稿；

- 提交；
- 查看所属门店允许查看的新增记录；
- 执行任务；
- 查看公告和 SOP。

不能：

- 访问其他门店；
- 作废正式记录；
- 标记管理员已查看；
- 创建任务模板；
- 发布或审核任务；
- 查看全局统计；
- 修改其他用户提交。

管理员可以：

- 查看授权门店；
- 标记查看；
- 作废；
- 导出；
- 创建模板；
- 发布和审核；
- 管理公告和 SOP；
- 查看统计。

RLS 必须防止用户通过修改 `store_id` 越权。

Storage Policy 必须与数据库权限一致。
