# StoreHub 钉钉考勤同步设计

## 同步范围

- 管理员手动：当前月、指定月、指定门店或单个员工。
- 自动每日：最近 7 个企业日期，用于处理接口延迟、补卡和后续修正。
- 自动月初：回补上月最后 5 天。
- 页面只查询 Supabase 本地标准化数据，不因打开页面触发钉钉 API。

## 幂等与修正

- 日记录唯一键：`corp_id + profile_id + attendance_date`。
- 打卡流水唯一键：`corp_id + dingtalk_record_id`。
- 目录唯一键：`corp_id + dingtalk_user_id`。
- 同步使用 Upsert；重复同步更新事实记录，不产生重复统计。
- 月摘要按员工和日期实时聚合；同一员工来自多个企业的记录不会重复计算出勤天数。
- 同一员工同日在两个企业都有有效排班时，明细保留全部企业来源并显示重复排班提醒。
- 跨日下班卡归属排班工作日；补卡和修正通过再次同步覆盖对应日记录。

## 批次与容错

- 日期每 7 天拆分，员工每 50 人拆分。
- Token 缓存提前 120 秒失效；Token 错误强制刷新后重试一次。
- 429/5xx 和超时指数退避，默认最多重试 3 次。
- 同步执行按员工隔离；单个员工失败写入 `attendance_sync_failures`，其余员工继续。
- 任务状态包括等待、执行中、成功、部分成功和失败；可从管理页面重试失败/部分成功任务。

## 状态标准化

内部状态覆盖正常、迟到、早退、缺卡、待打卡、休息、请假、出差、外勤和异常。无时区排班字符串按企业时区解析；应打卡时间未到时标记为待打卡，不计异常；钉钉排休标识优先判为休息。统计优先使用钉钉考勤结果与排班字段，前端仅负责中文显示、筛选和企业时区格式化。

## 审计与隐私

绑定、解绑、手动同步和重试写入审计日志。钉钉 AppSecret、Access Token、Cron Secret、完整手机号及完整第三方响应不落库、不进入浏览器、不打印到日志。

## 故障处理

1. 先看 `attendance_sync_jobs` 状态及汇总。
2. 查看 `attendance_sync_failures` 的阶段、错误码和是否可重试。
3. 检查钉钉应用可见范围、权限和员工绑定。
4. 修正后从管理页面重试，禁止通过删除或清空历史数据解决同步问题。
