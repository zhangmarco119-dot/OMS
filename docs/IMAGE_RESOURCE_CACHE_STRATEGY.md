# StoreHub 图片资源缓存策略

## 目标

用户已经打开并看到过的图片，在返回列表、重新进入详情或在相邻页面间切换时应直接显示，不应重复签名和下载。缓存不能改变原有权限，也不能让不同账号互相看到私有图片。

## 统一加载顺序

1. 优先读取当前登录会话的内存缓存。
2. SOP 图片可继续读取设备 Cache Storage。
3. 未命中缓存时才向 Supabase Storage 生成短期签名地址并下载图片内容。
4. 相同图片的并发请求合并为一次，多个组件共享同一个加载结果。
5. 浏览器不支持内容缓存或 Storage 响应不允许 JavaScript 下载时，自动退回原有签名地址显示方式。

缓存键由 Storage bucket、对象路径、显示规格和转换版本共同组成，不使用每次变化的签名 token。

## 隐私和容量

- SOP 列表图、详情图和原图可以使用 24 小时设备缓存。
- 任务提交图、任务参考图、到货照片和运营报告照片仅保留在当前登录会话。
- 内存缓存最多保留 150 项或 80 MB，超限后清理最久未使用的图片。
- 设备缓存最多保留 180 项或 120 MB，并按最近使用时间和 24 小时有效期清理。
- 登录其他账号或退出登录时，内存缓存和设备缓存都会清空。

## 图片更新

- 上传成功后直接把浏览器中已经压缩完成的图片写入缓存，因此当前页面立即显示，不再二次下载。
- 替换、删除 SOP 图片、任务图片、到货图片或运营报告图片时，旧对象对应的缓存立即失效。
- 图片对象路径或转换版本变化时会生成新缓存键，不会误用旧图。

## 验收

- 同一对象连续加载或多个组件同时加载，只签名和下载一次。
- 返回已经查看过的页面时图片立即从缓存出现。
- 上传成功后立即预览，离开再返回仍可复用。
- 删除或替换后不会继续显示旧图。
- 退出登录后缓存项和 Blob URL 均被清理。
