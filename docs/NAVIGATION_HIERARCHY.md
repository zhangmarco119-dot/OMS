# StoreHub 页面从属与返回规范

本文件是应用内返回行为的唯一业务层级说明。返回目标由页面的父子从属关系决定，不由“上一次访问了哪个 URL”决定。

## 基本规则

- 首页、工作台、待办、我的为一级平级入口；底部导航切换使用 `replace`，不形成返回链。
- 工作台中的功能卡片互为平级页面。功能页返回工作台；从首页明确提供的快捷卡片进入时，首页可作为该次合法父页。
- 同一功能中的标签、筛选、月份和排序属于平级状态，切换使用 `replace`，不形成返回链。
- 列表进入详情使用 `push`。详情返回列表，并恢复进入详情前的完整查询参数、页面状态和滚动位置。
- 多层详情逐层返回，例如“综合统计 → 员工工资 → 月度工资单”。
- 左上角返回、浏览器/手机原生返回和屏幕边缘返回使用同一套父子校验。只有浏览器前一项经过校验确实是业务父页时才执行历史回退，否则直接替换为规定父页。

## 一级平级入口

| 页面 | 路由 |
| --- | --- |
| 首页 | `/app` |
| 工作台 | `/app/workbench`（`/app/menu` 为兼容别名） |
| 待办 | `/app/todos` |
| 我的 | `/app/account` |

## 工作台功能页

以下页面的默认父页均为工作台：

- 员工功能：点货、订货、到货上报、任务中心、门店公告、SOP 手册、我的考勤、我的薪资、加班/兼职工时、运营历史、运营报告。
- 管理员功能：货品管理、账号管理、考勤管理、实时薪资、税务与记账、运营统计、操作日志、到货中心、任务管理、公告管理、SOP 管理。
- 首页存在的快捷卡片或通知可成为对应功能页本次进入的合法父页；未记录进入来源时仍回默认父页。

## 同页查询子层级

- 管理员实时薪资：功能标签是平级状态。
- 实时工资：员工详情的父级是保留月份、门店和搜索条件的员工列表。
- 综合统计：员工工资的父级是保留时间范围和搜索条件的统计列表；月度工资单的父级是该员工工资页。
- 工资单：查看或修改工资单的父级是保留月份、范围和员工选择的工资单列表。
- 员工我的薪资：工资单详情的父级是工资单列表。
- 修改密码、关联任务点货和到货编辑均按明确的查询子层级返回，不把其他查询状态误判成父页。

## 状态保存

- URL 中的月份、门店、搜索词等查询参数随父页完整保存。
- 组件级筛选状态通过 `useRememberedPageState` 保存在当前会话。
- 滚动位置以完整路由（路径加查询参数）保存；从子页返回父页时恢复，而新开无关页面时回到顶部。
