# 移动端门店盘点订货系统
## 产品需求文档（PRD）＋技术设计＋Codex Master Prompt

版本：V1.0  
适用门店：
- 宝珠奶酪（五道口店）
- OMEGA酸奶（西直门店）

---

# 一、项目概述

## 1.1 项目目标

开发一套主要在手机浏览器中使用的门店货品盘点与订货 Web 系统。

系统采用“一套程序、多门店数据隔离”的方式运行。员工使用各自账号登录后，系统根据账号绑定的门店自动加载对应门店名称、货品清单和业务数据。

首期支持两个门店：

1. 宝珠奶酪（五道口店）
2. OMEGA酸奶（西直门店）

两个门店的页面结构、操作逻辑和功能完全一致，仅门店标题、账号权限和货品清单不同。

## 1.2 使用对象

- 门店店长
- 门店员工
- 系统维护人员/管理员

## 1.3 核心设计原则

- 手机优先，兼容常见安卓和 iPhone 浏览器。
- 页面简洁、大方、清晰，适合非技术人员使用。
- 核心流程采用大按钮、少输入、强提示的“傻瓜式操作”。
- 一套代码支持多个门店，禁止为每家门店复制一套页面和逻辑。
- 门店之间的数据必须严格隔离。
- 盘点或订货过程中自动保存，避免误关页面或刷新后数据丢失。
- Excel 仅作为初始导入和结果导出方式，正式业务数据由数据库统一管理。
- 首期用户很少，应优先选择低成本、低维护量的 Serverless 架构。

# 二、推荐技术架构

## 2.1 推荐方案

### 前端

- React
- TypeScript
- Vite
- Tailwind CSS
- shadcn/ui 或同等级轻量 UI 组件库
- React Router
- React Hook Form
- Zod
- SheetJS（xlsx）用于浏览器端 Excel 导出
- PWA 支持，可添加到手机桌面

### 后端及数据库

推荐使用 Supabase：

- PostgreSQL 数据库
- Supabase Auth 用户认证
- Row Level Security 数据权限隔离
- Storage 用于保存导出文件或配置文件（可选）
- Edge Functions 用于必须在服务端执行的业务逻辑（按需使用）

### 部署

优先方案：

- Cloudflare Pages 部署前端
- Supabase 承担认证和数据库

备选方案：

- 腾讯云 EdgeOne Pages 部署前端
- Supabase 承担认证和数据库

## 2.2 不需要独立云服务器

本项目首期不运行常驻后台进程，不需要购买传统云服务器。

前端静态文件由 Pages 平台托管，账号认证、数据库和必要的服务端逻辑由 Supabase 提供。

## 2.3 架构要求

- 不允许把真实密码明文保存在前端配置文件中。
- 不允许将 Supabase Service Role Key 暴露到前端。
- 前端只能使用公开的匿名密钥，并依赖数据库 RLS 控制权限。
- Excel 中的账号密码配置仅可作为首次导入来源，导入后密码必须通过认证系统安全保存。
- 所有门店业务表必须包含 `store_id`。
- 普通员工只能查询和修改自己所属门店的数据。
- 管理员可按权限查看和维护多个门店。

# 四、角色与权限

## 4.1 普通员工

- 登录系统。
- 进入账号绑定的门店。
- 新建并完成盘点单。
- 新建并完成订货单。
- 修改自己当前尚未提交的草稿。
- 导出自己完成的盘点单或订货单。
- 上报停用货品、货品信息错误和新增货品。

## 4.2 店长

除普通员工权限外，可增加：

- 查看本门店历史盘点单。
- 查看本门店历史订货单。
- 重新导出历史单据。
- 查看待处理的货品维护反馈。
- 可选：查看本门店员工操作记录。

## 4.3 系统管理员

- 管理门店。
- 管理用户及门店绑定关系。
- 管理商品清单。
- 处理停用、信息错误和新增货品反馈。
- 查看全部门店历史记录。
- 导入 Excel 商品清单。
- 导入或创建账号。
- 禁用账号。
- 修改账号所属门店和角色。

# 五、登录与门店识别

## 5.1 登录页面

页面内容：

- 品牌或系统名称。
- 用户名输入框。
- 密码输入框。
- 登录按钮。
- 密码显示/隐藏按钮。
- 登录中状态。
- 登录失败提示。

## 5.2 登录逻辑

1. 用户输入用户名和密码。
2. 系统进行安全认证。
3. 获取用户资料及其绑定的 `store_id`。
4. 自动进入该门店首页。
5. 页面标题、货品和历史数据均根据 `store_id` 动态加载。
6. 用户不得通过修改网址访问其他门店数据。

## 5.3 登录状态

- 支持保持登录状态。
- 长时间未操作后可要求重新登录。
- 提供明确的退出登录按钮。
- 登录失效时应先保存本地草稿，再引导重新登录。

# 七、盘点货品功能

## 7.1 新建盘点任务

点击“盘点货品”后：

1. 检查当前账号是否有未完成盘点草稿。
2. 若有，提示继续或重新开始。
3. 若没有，创建新的盘点任务。
4. 读取当前门店所有启用状态的货品。
5. 按后台设置的排序顺序生成盘点明细。

创建任务时应保存一份货品快照，防止盘点过程中后台修改商品后影响当前单据。

## 7.2 手机端页面布局

原始需求中的左右列表适合电脑宽屏，但手机屏幕不适合长期展示三栏。因此要求采用响应式设计。

### 手机端

顶部区域：

- 返回首页按钮。
- 标题：`OMEGA酸奶（西直门店）盘点系统`
- 当前进度，例如 `12 / 58`
- 可视化进度条。
- 自动保存状态：`已自动保存`、`正在保存`或`保存失败`。

中央操作卡片：

- 货品名称，只读。
- 货品规格，只读。
- 数量输入框。
- 点货单位，只读并显示在输入框右侧。
- 当前货品备注或异常状态。
- 上一个按钮。
- 下一个按钮。
- 跳到下一个未盘货品按钮。

底部固定操作区：

- 标记不再使用。
- 标记信息有误。
- 结束盘点。

货品导航：

- 使用“已盘”和“未盘”两个标签页或底部抽屉。
- 每个列表可上下滚动。
- 点击货品可直接跳转。
- 已盘货品显示已填写数量。
- 未盘货品显示序号和名称。
- 当前货品高亮。
- 可显示搜索框，按货品名称快速查找。

### 平板和电脑端

- 左侧：已盘货品列表。
- 中间：当前货品操作卡片。
- 右侧：未盘货品列表。
- 三栏均保持良好可读性。
- 两侧列表固定高度、独立滚动。

## 7.3 数量输入

- 默认空值，不要默认填写 0。
- 支持整数和小数。
- 小数位数根据单位或系统规则控制，默认最多两位。
- 不允许负数。
- 输入后自动保存。
- 点击“下一个”时校验当前输入。
- 手机端应弹出数字键盘。
- 已填写 `0` 表示确实盘点为零，应视为“已盘”。
- 空值表示尚未盘点。
- 要明确区分空值与数字 0。

## 7.4 上一个和下一个

- “上一个”切换到清单中的上一个货品。
- “下一个”切换到下一个货品。
- 到达第一个或最后一个时按钮禁用。
- 切换前自动保存当前输入。
- 不允许因快速点击造成数据错位。

## 7.5 跳到未盘货品

提供明显但不抢眼的快捷按钮：

> 下一个未盘

点击后：

- 按货品清单排序，跳转到当前项目之后的第一个未盘货品。
- 如果后面没有，则从清单开头寻找。
- 如果全部完成，提示“所有货品均已盘点”。

## 7.6 已盘和未盘列表

### 已盘货品

显示：

- 序号。
- 货品名称。
- 已填写数量。
- 单位。
- 异常标识。

点击任意项目可跳转并修改。

### 未盘货品

显示：

- 序号。
- 货品名称。
- 规格。
- 单位。

点击任意项目可跳转并填写。

## 7.7 标记货品不再使用

点击后弹出确认框：

> 确认将该货品标记为“不再使用”吗？该操作不会立即从正式货品清单中删除，只会随本次盘点单上报给维护人员。

可选填写备注。

保存内容包括：

- 标记类型。
- 原货品信息。
- 操作人。
- 操作时间。
- 备注。
- 所属盘点单。

该货品仍需要允许填写实际库存数量，也允许选择“不填写数量，仅上报”，但系统必须明确展示其状态。

## 7.8 标记货品信息有误

点击后打开表单，显示原信息并允许员工填写建议修改值：

- 建议货品名称。
- 建议规格。
- 建议点货单位。
- 问题说明。

重要规则：

- 不直接修改正式货品清单。
- 当前盘点单仍保存原始货品快照。
- 建议修改内容作为维护反馈单独保存。
- 导出的盘点单中同时显示原信息和建议修改信息。

## 7.9 自动保存和草稿恢复

- 每次填写、修改、标记后自动保存到数据库。
- 同时可将当前编辑状态保存到本地存储作为临时兜底。
- 刷新页面、切换页面或误关闭浏览器后，可以继续。
- 页面显示最后保存时间。
- 网络中断时显示离线/待同步状态。
- 恢复联网后自动重试。
- 提交时以服务端数据为准，并进行完整性校验。

## 7.10 结束盘点前校验

点击“结束盘点”时：

- 检查是否仍有未盘货品。
- 若存在未盘货品，显示数量和列表。
- 提供：
  - 返回继续盘点
  - 跳到第一个未盘
  - 仍然进入汇总页（仅管理员或设置允许时）
- 默认不允许普通员工在存在未盘货品时直接最终提交。
- 被明确标记为不再使用且选择无需填写数量的项目可以视为已处理。

## 7.11 盘点完成汇总页

顶部醒目显示：

> 货品已清点完毕，您辛苦了。

显示汇总信息：

- 门店名称。
- 盘点时间。
- 操作账号。
- 货品总数。
- 已盘数量。
- 异常货品数量。
- 新增货品数量。

三个主要按钮：

1. 返回修改
2. 继续增加货品
3. 结束盘点并导出盘点单

## 7.12 返回修改

- 返回盘点页面。
- 保留全部数据。
- 可从已盘列表选择任意货品修改。
- 修改后重新点击结束盘点。

## 7.13 继续增加货品

打开新增货品表单：

- 货品名称，必填。
- 规格，必填。
- 数量，必填，可为 0。
- 单位，必填。
- 备注，选填。

新增项目：

- 只添加到当前盘点单。
- 自动标记为“新增货品”。
- 不直接写入正式货品主表。
- 提示后台维护人员审核后决定是否加入货品清单。
- 允许一次新增多个货品。
- 允许在最终提交前修改或删除本次新增项。

## 7.14 最终提交

点击“结束盘点并导出盘点单”后：

1. 服务端再次校验数据。
2. 将任务状态改为 `submitted`。
3. 记录最终提交时间。
4. 提交后普通员工不能直接修改。
5. 生成 Excel。
6. 打开系统分享流程或下载文件。
7. 保留历史记录，可再次导出。

为防止重复提交：

- 按钮点击后立即进入处理中状态。
- 使用幂等逻辑。
- 重复请求只能得到同一份已提交结果。

# 八、申请订货功能

订货系统与盘点系统共享同一套通用任务框架和页面组件，不允许复制大量代码。

## 8.1 差异

- “盘点数量”改为“订货数量”。
- 页面标题改为“订货系统”。
- 增加“无需订货”按钮。
- 导出文件改为订货单。
- 完成文案改为订货完成文案。

## 8.2 无需订货

点击后：

- 当前货品状态设为 `no_order_needed`。
- 数量保持空值。
- 该货品视为已处理。
- 列表中显示“无需订货”标签。
- 再次进入时允许取消“无需订货”并填写数量。

不得使用数字 0 替代“无需订货”，因为：

- 0 可能表示明确订货数量为零。
- “无需订货”是业务状态，应独立保存。

## 8.3 订货完成页

显示：

> 本次订货信息已填写完毕，您辛苦了。

按钮：

1. 返回修改
2. 继续增加货品
3. 结束订货并导出订货单

## 8.4 导出信息

订货单至少包含：

- 单据编号。
- 门店名称。
- 操作账号。
- 开始时间。
- 提交时间。
- 货品名称。
- 规格。
- 订货数量。
- 单位。
- 无需订货状态。
- 货品异常状态。
- 员工备注。
- 新增货品标识。

原始需求中“订货完成后生成 Excel 的盘点单”应修正为“生成 Excel 订货单”。

# 九、Excel 导入规范

## 9.1 商品清单文件

初始商品清单 Excel 包含两个 Sheet：

- `宝珠奶酪（五道口店）`
- `OMEGA酸奶（西直门店）`

建议列名：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 货品名称 | 是 | 商品显示名称 |
| 规格 | 是 | 如 1kg/袋、12瓶/箱 |
| 点货单位 | 是 | 盘点及订货填写单位 |
| 排序 | 否 | 数字，越小越靠前 |
| 启用状态 | 否 | 默认启用 |
| 货品编码 | 否 | 建议后期增加且唯一 |

导入规则：

- 去除首尾空格。
- 空白行忽略。
- 同门店内货品名称、规格、单位完全相同时提示可能重复。
- 缺少必填字段时整行报错。
- 导入前提供预览和错误报告。
- 不因部分错误而静默丢失数据。
- 正式导入应记录导入批次、导入人和时间。

## 9.2 用户配置文件

不建议长期使用明文账号密码 Excel。

可保留初始化模板，建议列名：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 用户名 | 是 | 登录名 |
| 初始密码 | 是 | 仅首次创建账号使用 |
| 姓名 | 否 | 员工姓名 |
| 门店 | 是 | 必须与门店表匹配 |
| 角色 | 是 | employee、manager、admin |
| 启用状态 | 否 | 默认启用 |

导入要求：

- 密码不得写入普通业务表。
- 通过 Supabase Auth 创建用户。
- 首次登录可强制修改初始密码。
- 配置文件不得提交到公开 Git 仓库。
- `.gitignore` 必须忽略真实配置文件。
- 仓库只保留脱敏模板。

# 十、Excel 导出规范

## 10.1 文件命名

盘点单：

```text
盘点单_OMEGA酸奶（西直门店）_2026-07-10_173500.xlsx
```

订货单：

```text
订货单_宝珠奶酪（五道口店）_2026-07-10_173500.xlsx
```

## 10.2 工作表结构

建议至少包含两个 Sheet。

### Sheet 1：单据明细

# 十二、数据权限与安全

## 12.1 RLS 基本规则

普通员工：

- 只能读取自己的 profile。
- 只能读取自己门店的启用商品。
- 只能创建自己门店的任务。
- 只能读取和修改自己门店中由自己创建且未提交的任务。
- 不能修改已提交任务。
- 不能读取其他门店数据。

店长：

- 可查看本门店全部任务。
- 是否可修改员工草稿由业务规则决定。
- 不能访问其他门店。

管理员：

- 根据管理员权限查看和维护对应门店或全部门店。

## 12.2 安全要求

- 所有表必须启用 RLS。
- 所有关键权限都在数据库侧验证，不能只依赖前端隐藏按钮。
- 密码必须由认证服务处理。
- 环境变量不得提交到 Git。
- 导出文件中避免包含密码、Token 或内部密钥。
- 对登录尝试进行合理限制。
- 错误日志不得泄漏敏感信息。

## 13.1 整体风格

- 简洁、优美、现代。

- 主要按钮高度建议 48–56 px。
- 数量输入框醒目。
- 底部按钮避开 iPhone 安全区域。

- 不使用过小文字。

- 放弃草稿。
- 标记不再使用。

- “数量不能为空，请填写 0 或实际数量。”

避免只显示“操作失败”。

# 十六、业务状态定义

## 16.1 任务状态

- `draft`：进行中，可编辑。
- `review`：已进入完成汇总页，仍可返回修改。
- `submitted`：已最终提交，不可由普通员工修改。
- `cancelled`：已取消。

## 16.2 明细完成状态

- `pending`：未处理。
- `completed`：已填写数量，数量可为 0。
- `no_order_needed`：仅订货任务使用，无需订货。

## 16.3 异常类型

- `discontinued`：货品不再使用。
- `incorrect`：货品信息有误。
- `new`：本次新增货品。

一个明细是否允许同时存在多个异常，应在实现时优先支持多标签；若数据结构首期只支持单值，则必须明确限制并在 UI 中说明。更推荐单独建立 `product_feedback` 表支持多个反馈。

## 17.1 性能

- 常见 100–500 个商品时操作流畅。

- 草稿恢复。
- 网络异常重试。
- 防重复提交。
- 数据库迁移可回滚。

- 关键操作有日志。

- TypeScript 严格模式。
- 业务逻辑与 UI 分离。
- 盘点和订货复用通用组件。
- 数据库类型自动生成。

必须包含：

- 门店盘点系统标题。
- 当前进度数字和进度条。
- 当前商品名称，只读。
- 当前商品规格，只读。
- 数量输入框。
- 单位只读显示。
- 上一个。
- 下一个。
- 下一个未盘。
- 已盘商品列表。
- 未盘商品列表。
- 列表点击跳转。
- 标记货品不再使用。
- 标记货品信息有误。
- 结束盘点。
- 自动保存状态。

手机端不要硬塞三栏。使用标签页、抽屉或底部面板展示已盘和未盘列表。平板和电脑端可以三栏显示。

数量规则：

- 空值代表未盘。
- 数字 0 代表已盘且库存为 0。
- 支持合理小数。
- 禁止负数。
- 切换商品前保存。
- 输入后防抖自动保存。

### 货品不再使用

- 弹出确认。
- 可填写备注。
- 不直接删除正式商品。
- 作为维护反馈保存并在 Excel 标记。

### 货品信息有误

允许填写建议：

- 名称。
- 规格。
- 单位。
- 问题说明。

不得直接改变当前正式商品，保存原商品快照和建议修改值。

### 完成盘点

结束前检查未盘商品。

所有项目处理完成后进入汇总页，显示：

- “货品已清点完毕，您辛苦了。”
- 返回修改。
- 继续增加货品。
- 结束盘点并导出盘点单。

新增货品表单：

- 名称。
- 规格。
- 数量。
- 单位。
- 备注。

只加入当前单据并标记“新增货品”，不直接加入正式商品表。

### 订货

复用盘点流程，但：

- 数量为订货数量。
- 增加“无需订货”按钮。
- 无需订货是独立状态，不能简单等同于数量 0。
- 完成后生成订货单，而不是盘点单。

### 导出和分享

生成 xlsx 文件，包含：

- 单据编号。
- 单据类型。
- 门店。
- 账号和员工姓名。
- 开始、提交、导出时间。
- 商品名称。
- 规格。
- 数量。
- 单位。
- 无需订货状态。
- 异常类型。
- 建议信息。
- 备注。
- 新增商品标记。

优先使用 Web Share API 分享文件。浏览器不支持文件分享时，自动下载并显示清楚提示。不得假设所有浏览器都能直接分享到微信。

### 历史记录

- 查看已提交盘点单和订货单。
- 查看明细。
- 重新下载。
- 重新分享。
- 普通员工、店长和管理员按权限访问。

- 显示保存状态。
- 网络恢复后重试同步。
- 最终提交服务端校验。
- 最终提交使用幂等机制，防止重复单据。
- 导出失败不得导致业务数据回滚或丢失。

## 9. UI 要求

- 手机优先。
- 简洁、大方、现代、优美。
- 大按钮和清晰反馈。

- 数字输入使用手机数字键盘。
- 兼容 iPhone 安全区域和安卓浏览器。
- 软键盘不能遮挡当前输入。
- 不依赖 hover。
- 当前商品高亮。
- 未完成、完成、异常状态清楚。
- 对放弃草稿、删除新增商品和最终提交进行确认。

## 10. 安全

编写并测试 RLS 策略，确保：

- 员工只能看到所属门店商品。
- 员工只能操作所属门店任务。
- 员工不能访问其他门店。
- 员工不能修改已提交单据。
- 店长只能查看本店。
- 管理员按授权范围管理。
- 修改 URL 或直接调用 API 也不能越权。
