# 实时预估薪资

系统按 `员工实时预估工资计算标准.md` 计算员工从当月 1 日到所选截止日期已经产生的工资，不预测月末金额。界面始终标记“预估”，最终工资以管理员月末确认为准。

## 统计口径

- 基本工资、房补和绩效均按出勤天数折算，不展示或使用出勤小时。
- 全部授权门店范围内，同一员工同一天在多个门店出勤只计 1 天。
- 迟到、缺卡和异常合并所有授权门店记录；考勤页面选择单一门店时只显示该门店数据。
- 提成只汇总管理员在员工工资规则中指定的门店，并只使用截止日期之前已确认的每日营业收入。
- 任务或营业收入缺失时，对应金额显示“待更新”，不能作为完整最终金额。
- 李荣珊、李荣妹、李荣美按兼职小时工资另行计算，不进入本实时预估模型。

## 管理员流程

工作台进入“实时薪资”，可使用五个功能页签：

1. 实时工资：查看员工明细、已知项预估合计和数据完整状态。
2. 员工参数：设置基本工资、房补、满绩效、提成比例、提成门店及生效日期。
3. 绩效规则：设置三项权重、迟到扣分、等级区间和金额系数。
4. 营业收入：按门店和日期录入已确认收入。
5. 处罚：分别记录罚款金额和绩效扣分，并支持保留原因后撤销。

所有参数按生效日期保存历史。员工参数必须经管理员勾选确认，才会被视为完整数据。

## 数据库实现

- `payroll_employee_rules`：员工工资参数历史。
- `payroll_employee_commission_stores`：员工提成门店。
- `payroll_performance_rules`：绩效规则历史。
- `payroll_store_revenues`：每日已确认营业收入。
- `payroll_penalties`：其他罚款和纪律扣分。
- `get_payroll_estimate`：员工本人或有权限管理员读取单人预估。
- `admin_payroll_estimates`：管理员读取人员列表与合计。

截止日期统一使用北京时间，避免 Supabase UTC 日期在北京时间凌晨误判为未来日期。
