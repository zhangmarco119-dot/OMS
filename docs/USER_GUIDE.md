# 使用说明

## 登录

打开 `/login`，输入管理员在后台设置的账号名或姓名及密码。账号名是唯一登录标识；如果多人姓名相同，需要改用账号名。登录后系统会根据 `profiles.store_id` 自动进入对应门店首页，用户不需要知道 Supabase Auth 的底层邮箱。

## 盘点

1. 在首页点击“盘点货品”。
2. 对当前商品填写数量；空值表示未处理，`0` 表示已处理且数量为 0。
3. 使用“上一个”“下一个”“下一项未处理”切换商品。
4. 手机端可打开“已点 / 待点”抽屉查看列表并跳转。
5. 盘点过程中可随时点击“结束盘点”进入汇总页，不要求所有商品都填写。
6. 在汇总页点击“提交本次点货”。未填写商品会以“未盘点”保存，系统同时在管理员消息中心生成提醒。
7. 点击顶部“导入历史盘点单”可查看本门店所有账号提交的历史盘点单。列表显示提交人、时间、商品总数、已盘点和未盘点数量，选择后会把匹配商品的数量和状态导入当前草稿。
8. 自动保存继续在后台运行，但页面不再显示频繁变化的保存状态文字。

## 订货

1. 在首页点击“申请订货”。
2. 对当前商品填写订货数量，或点击“无需订货”。
3. 所有商品处理完成后点击“结束订货”进入汇总页。
4. 在汇总页点击“提交本次订货”。系统会完成本次提交，并在管理员消息中心生成提醒。

## 店长商品反馈

店长在点货和订货页面均可处理当前商品资料：

- 点击“信息有误”打开商品编辑表单。提交后立即更新本店商品名称、规格、单位和商品编码，同时在管理员后台生成一条修改通知。
- 管理员可对修改通知点击“我知道了”，也可以二次确认后点击“撤回修改”，恢复修改前的数据。
- 点击“不再使用”会先显示确认界面。确认后只提交删除申请，商品不会立即删除，页面显示“已提交删除此商品”。
- 提交删除申请后，该商品立即从待点列表移到已点列表，并显示“申请删除”标签。
- 管理员可忽略删除申请，或在再次确认后从商品数据库删除。历史点货和订货单仍保留原商品快照。
- 点击“新增商品”填写名称、规格、单位、数量及可选编码。店长保存后会同时新增本店商品主数据、当前任务项和管理员通知；管理员可点击“忽略”或“我知道了”。
- 普通员工使用“新增商品”时只增加本次任务的临时商品，不直接写入商品数据库。

## 提交和管理员消息

- 员工提交点货或订货后，业务数据以数据库记录为准。
- 提交不再强制导出 Excel，也不需要员工下载文件。
- 管理员登录后进入消息中心，可看到最近提交的点货/订货提醒。
- 消息中心的已读状态保存在当前浏览器本机，提交记录本身仍保存在数据库。

## 历史记录

打开 `/app/history`：

- 可按全部、盘点、订货筛选。
- 员工只显示自己已提交的单据。
- 店长显示本门店已提交单据。
- 管理员显示 RLS 授权范围内的全部门店记录。
- 点击“查看明细”可查看每次点货/订货的商品、规格、数量和状态。

## 后台管理

管理员打开 `/app/admin`：

- 商品：新增、编辑、停用或删除当前门店商品。
- 导入：上传 Excel 批量导入商品。默认读取第一个 Sheet。
- 账号：创建账号、修改角色/门店/状态、设置临时密码或删除账号。门店权限支持多选；创建账号时邮箱选填，不填时系统自动建立内部认证邮箱。

商品反馈位于管理员“记录”页面。卡片可点击展开；修改通知支持“我知道了 / 撤回修改”，删除申请支持“确认删除 / 忽略”。

子账号登录后，可在首页“当前门店”下拉框切换已授权门店。删除账号会阻止该账号继续登录，但历史点货和订货记录仍保留原提交人姓名。

商品导入支持列名：

- 商品名称
- 规格
- 单位
- 商品编码
- 排序
- 启用

导入时优先用商品编码匹配已有商品；没有编码时使用“商品名称 + 规格 + 单位”匹配。匹配到则更新，未匹配则新增。
