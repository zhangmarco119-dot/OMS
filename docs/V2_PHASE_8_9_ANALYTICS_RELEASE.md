# 门店运营系统 V2 阶段 8 与 9

## 阶段 8：统计与历史中心

- `/app/admin/analytics` 使用 `admin_v2_analytics` RPC 聚合授权门店数据：到货趋势、数量、产品种类、任务状态、门店完成率、巡店问题、整改完成率以及 V1 摘要。
- `/app/operations-history` 作为跨模块历史入口，链接点货订货、到货和任务记录，并保留既有角色范围。
- 管理员首页改为紧凑关键指标，不在首页重复渲染“今日到货”详情模块。

## 阶段 9：上线、性能与回滚验证

- 前端不引入新依赖；趋势图使用原生 CSS，避免增加移动端包体积。
- 底部导航改为精确路由匹配，避免多按钮同时高亮；核心功能收纳到“更多”二级入口。
- `0025_v2_analytics_history.sql` 仅新增安全定义的聚合 RPC，不修改 V1 表和既有 migration。
- 发布前执行：schema 校验、安全扫描、类型检查、lint、单元测试、生产构建和桌面/移动端冒烟测试。

## 生产检查清单

1. 在 Supabase 确认迁移 `0023` 至 `0025` 均已部署。
2. 使用员工、店长、管理员各一账号验证 V1 点货/订货与 V2 新入口范围。
3. 使用窄屏设备检查四项底部导航仅有一项高亮，打开“更多”验证二级入口。
4. 在管理端创建任务、退回一项整改、员工重新提交，并验证高亮及审核历史。
5. 以 Cloudflare Pages 预览部署运行同一套 build 输出，再提升为生产部署。
