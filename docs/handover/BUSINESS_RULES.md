# 业务模型与不可回归的交互约定

更新至 2026-11-25。主入口见 [接手总指南](../AGENT_HANDOVER.md)。以下综合用户需求、现有实现与版本记录；具体字段/RPC 以最新代码及迁移为准。旧需求若被后续版本覆盖，采用后续规则。

## 登录、员工、权限

- 账号名或姓名登录，经 `account-login` 服务端查 profiles 后用 Auth 校验密码；同名不唯一时要求账号名，不暴露内部认证邮箱。
- `admin-users` 创建账号、重置临时密码，只允许有权限管理员。Auth 用户、profile、门店关联及软删除要保持一致。
- 管理员菜单名称是“员工管理”，含账号管理和员工信息管理；“薪资管理”替代旧“实时薪资”模块名。
- 员工身份证、电话、地址、银行卡、开户行与税务记账的人员登记为同一套联动数据；不要复制成两张互不同步的名册。
- 税务人员可无登录账号；编辑薪资对应选中的月份，不是系统当前月份。不要增加另一个“补录”按钮绕过月份错误。
- 历史月份员工范围按当时存在的关系、考勤与规则判断；新绑定员工不能只从绑定后昨天开始计算历史出勤。
- 停用/离职/软删除与历史查看分离，历史罚单、工资单、任务提交人仍应可见。

## V1 点货、订货与货品主库

- `tasks` / `task_items` 共用模型，`task_type` 区分 inventory/order；商品快照保持历史名称、单位和规格。
- 数量输入、未处理定位、抽屉与草稿自动保存按移动操作设计；无填数量的点货项不可默认为已完成零库存。
- 店长从任务中更正/新增货品通过原子 RPC，同时改主库、快照、管理员通知与操作日志。
- 员工也可以归档货品；归档可还原，区别于物理删除，不损坏历史快照。
- 员工删除申请由管理员许可；管理员可对同一批分别删除、归档、拒绝。已经待审批的旧删除申请也能选择归档，不只针对新增申请。
- 到货名称模糊检索包含归档货品；成功上报归档货品后取消归档、回到货品清单。避免只是前端显出来，数据库仍 archived。
- 管理员审批关联点货的 V2 任务时可进入选择模式，对个别条目局部驳回；员工重做的点货单仅含被驳回条目，已通过结果保留，重新提交只更新这些条目。
- 勾选框在开始批量/部分选择时才出现；退出选择模式恢复普通浏览。

## 到货上报、中心与统计

- 到货草稿、商品条目、照片独立建模；更正/作废/审批要同步通知、统计与审计。
- 管理员到货中心及汇总均有商品检索；卡片可进入对应报告/对应商品详情。
- 在时间区间内搜单个商品后，可单独看该商品总量与每笔到货日期、时间、数量；按名称与单位归组，单位不同不得直接相加。
- 时间范围数据必须完整分页获取，列表、合计、导出用同一份筛选结果，不能只统计接口默认前 1000 条。
- 手机检索框不溢出，筛选不遮挡操作；图片阶段不得阻塞报告元数据。

## V2 模板、发布、执行、审批

- 模板可改名称、分组、内容、适用门店与参考图；发布后生成不可变版本快照，历史任务继续使用原版本。
- 发布前预览应复用员工真实任务呈现（`TaskExecutionPreview` 等），不能另做一个与实际不同的示意页面。
- 一次/周期任务的清单加载、适用门店、接收角色、发布时间与首期日期独立处理；模板空列表必须有正确错误/空状态，不能吞错误。
- 管理员待办支持选多个待审任务，一键通过或拒绝；当前服务器整批 RPC 负责授权、状态、通知与审计，防止逐个请求的一半成功状态。
- `batchReview` 会限制可选对象并统计结果；不将无关通知/工时审批混入同一任务 RPC。
- 批量任务审批与点货条目选择各有选择模式，不常驻 checkbox。
- 处理完成后旧异步待办加载结果不得把已处理项插回；按请求代次/失效检查保留最新服务器结果。

## 货品登记（西直门员工及店长）

- 工作台独立入口；五类为打包货品、遗弃货品、借用到五道口、设备、其他，各有独立菜单/登记列表。
- 管理员可实时查看，不能改员工登记；员工侧按权限保存、修改与删除。
- 第一行货品名称，可从当前门店货品库检索并填单位；搜不到可手动新建登记名称，不强迫创建主库商品。
- 数量与单位同一行；不显示“匹配结果”提示；移除货品备注项和顶部多余说明，分类按钮紧凑。
- 每个登记条目至少一张照片。增条目按钮放在最后一个条目下面，新条目追加底部。
- 过程实时保存到服务器，退出重进仍在；自动保存不整页刷新，不跳焦点，不因 updated_at 变化把卡片插到顶上。
- 已保存的跨端可见性依赖订阅/刷新；未提交输入和登录会话依然是设备本地状态，不宣称自动同步未保存草稿。

## 处罚

- 员工选择仅显示有效在职人员；停用人员旧处罚记录可查看。
- 店长开罚单的图片选择、预览、失败重试与管理员一致；发布后管理员收到待办。
- 罚款 0 元也是有效处罚记录，可能有扣分/原因/照片，不能用 truthiness 或 amount>0 从罚单列表过滤掉。
- 管理员处罚卡片标发布人；整卡点开详情，里面包含完整原因和上传图片；撤销按钮放详情下方，不占列表卡片。
- 员工从预估工资/工资单逐笔罚款可进入原因与图片；Storage RLS 要允许本人读自己的处罚图。
- 记录撤销保留原因/审计，按现有规则重新计算，不物理清掉历史证据。

## 钉钉考勤

- 页面读本系统保存的标准化结果，打开考勤/工资页不即时查钉钉。手动指定月份同步重查补卡，不把覆盖标记当永不过期缓存。
- 企业不同，AppKey/AppSecret/CorpId 与员工绑定必须对应；设备 OAuth 授权不是企业内部应用凭据的替代品。
- 源托管 Edge Function Secrets 不随普通数据库 dump 自动迁移。当前已有私有配置索引，不应未查文件就反复要求用户输入。
- 同步按员工/日期拆分、保存进度、幂等 Upsert；成功无排班也记覆盖，避免重复扫历史、耗尽每日额度。
- 新绑定员工的历史回补、月初上月补卡都要覆盖；跨门店关系按打卡所属日期有效关联判断。
- 补卡消除缺卡后仍保留钉钉判定迟到/早退和实际时长；`NotSigned` 占位计划时间不算真实打卡。
- 历史异常复查与失败重试看 jobs、failures、coverage，区分部分成功、超时、未配置和权限错误。
- 工资单生成使用已同步数据，不依赖钉钉可用性/额度。想更新补卡先独立同步考勤，再生成草稿。

## 薪资、个税、工资单

- 按员工、月份、截止日期计算已产生的预估薪资，采用北京时间；工资与绩效规则有生效历史，不能把今天的配置无条件套历史。
- 整月满勤基准为自然月天数减 4；全勤奖/超勤奖个人门槛可配置，独立于基本工资折算分母。
- 节假日补贴已从早期人工金额发展为按节假日实际出勤自动计算并保留管理员调整能力；2026 年 10 月业务口径是 1/2/3 日，基础计算为底薪 2200÷(当月天数−4)×相应出勤日数，历史手动覆盖、关联日期等以最新 SQL 为准。
- 累计提成根据实际出勤天数与同月满勤基准折算；收入基数来自管理员选定门店的月累计收入，不能误用当日营业额或同时叠加手工与平台来源。
- 多门店同一天出勤不重复计天；绩效按有效门店、关联日期和分配规则处理，保留月度手动等级/分数/金额覆盖。
- 员工可设置默认绩效等级；月度单独设置优先级和自动计算不被默认值破坏。
- 管理员可按员工与月份新增自定义项目名称、金额（另奖/补贴等）；实时薪资、最终工资单、统计图表都要计入，不能只改其中一个界面。
- 员工只展示薪资结果及必要明细，不显示管理员公式、评分比例、手动来源或开发说明；节假日项用“节假日补贴”。
- 全职自主延时登记审批通过后补贴 25 元/小时；兼职使用单独时薪，“兼职工时”名称贯穿入口/审批/统计。
- 申请修改使旧审批失效并重走对应审批；店长/管理员分级、时薪快照、可登记日期与半小时步长保持原规则。
- 罚款、个税扣除分别保留明细；零元罚单存在，但不等于要给已核实月薪为零的人发送空工资单。工资单零值跳过与处罚零值保留是两个不同需求。
- 工资单草稿→发送→确认/撤回；生成草稿不通知员工；发送才产生待办。修改已确认单据需清除旧确认并重新确认。
- 发送工资单固定快照，后续考勤/参数变化不静默重写。最终员工工资单与预估页均带参考水印；水印颜色更深、字号更大、分布紧密但不遮挡操作。
- 薪资综合统计、导出图表包含节假日补贴及适用项目，人数、门店分摊、收入/实发口径同步修改。
- 个税登记和报税信息按所选月份读取/保存，未绑账号人员历史月薪可编辑；从税务工资入口跳转对应月份来源，再返回保留月份。

## 关店与营业收入

- 西直门关店生效日由用户明确为 **2026-10-01**，不是提出需求的 10 月 31 日。当前经营状态需读门店配置，不能硬编码永远关闭。
- 关店后停止该店营业额同步、提成/绩效累计和相应营业报告入口；关店前历史保留可查可结算。
- 服务端必须拦截关店日期业务写入/绑定，不能只隐藏入口。恢复营业也通过带生效日的设置，不删历史关联。
- 银豹/企迈分页获取有效单据，排除作废、扣减退货；仅保存核算必要字段，不留顾客资料或完整第三方响应。
- 当日收入、月累计手工基数、平台同步是独立来源；允许同一自然月沿用最近有效来源日期，不跨月借上月收入。

## SOP、图片、日志与 AI

- SOP 管理移动端末尾能连续添加步骤、定位新步骤，键盘和底部栏不能遮挡编辑区；详情/列表按需渐进加载图片。
- 所有图片页面先显示正文/布局，图片异步签名/下载/解码，预留尺寸并显示“正在加载图片”；确实失败后才显示“图片预览加载失败”，不替换整个页面。
- 缓存按 bucket/path/规格/版本，合并同图并发；私有图片缓存受会话隔离，退出/换账号清理。SOP 设备缓存限时限容，任务/处罚等遵循对应会话策略。
- 参考图经 public backend 的 fallback 也必须解析正确 URL；原图查看支持双击、捏合缩放、拖动，不强制下载全尺寸图库。
- 操作日志每次实际发生逐条展示，明确时间；只有同一请求重试幂等去重，不能把不同员工/月次或多次查看合并成一行。
- 错误加载不能显示“当前没有待办”假结果，也不要显示网关 HTML；可重试只读请求，写请求不盲目重试造成重复业务。
- AI 提供建议/草稿，不越过原审批权限；入口加载不依赖慢网络配置。未经用户授权不要通过真实模型调用验证入口，使用 mock 和确定性规则测试。

## 视觉、布局和导航设计

- 统一浅色界面，`tailwind.config.ts` 的 ink `#16212f`、canvas `#f5f7f5`、surface 白色、line `#d7dde7`；品牌绿 500/600/700 为 `#1b8f65` / `#14734f` / `#105b40`，提示黄 accent 500 为 `#e0a400`。优先使用现有语义 token，不为单页另造一套配色。
- 字体 Inter/system-ui，最小宽度 320px；手机表单字号 16px，触控按钮最小高 44px；保持 focus-visible 与无障碍 aria 标签。日期/月/时间输入强制浅色，避免系统暗色导致字不可见。
- 共用 `PageShell`：手机 px-4，宽屏递增到 px-6/8，主体 max-w-5xl，默认 gap-5，居中标题与左返回；卡片/浮层/弹框使用既有 shadow-card/floating/dialog/panel。
- 页面 `100dvh`，底部导航占 `5.25rem + safe-area-inset-bottom`；`MobileActionBar`、dialog、相册选择、软键盘应兼容安全区，不用随意 fixed 元素覆盖 SOP 最后一步或表单按钮。
- 复用 `Surface`、`FormField`、`Actions`、`ActionFeedbackDialog`、`SuccessToast`、`MonthPicker`、`ProgressiveImage`、`ImageViewer`。月选择器应保留当前筛选状态，不因时区进入相邻月。
- 首页/工作台/待办/我的为平级入口，底栏切换 replace；标签、筛选、月份和排序也不积累返回历史。列表到详情 push，返回恢复原筛选和滚动。
- 返回遵循业务父子层级，不能简单 `navigate(-1)`。复用 `useBusinessBack`、`HierarchicalBackGuard`、`navigationHierarchy`、`useRememberedPageState`、`RouteScrollReset`；原生 Android 返回和网页左上返回保持同一判断。
- 任务中的 SOP/公告/关联点货是任务子流程，完成回原任务。由首页或待办进入的详情可有该次合法父页，不强制跳到另一个模块首页。
- 原始规范见 `docs/NAVIGATION_HIERARCHY.md`、`docs/UI_UX_REDESIGN_PLAN.md`；页面最新细节仍以共用组件、CSS 与测试为准。
